# 세션 유지 이슈 분석 및 해결

## 1. 현재 상황 (As-Is)
- **증상**: 사용자가 로그인 후 새로고침(F5)을 하면 로그인이 풀리는 현상 발생.
- **원인 추정**:
    1. `AuthContext.jsx`의 `initAuth` 함수가 실행되지 않거나, 실행 도중 에러가 발생하여 `user` 상태를 `null`로 설정함.
    2. `jwtDecode` 과정에서 토큰의 필드(`cognito:username` 등)가 예상과 달라 사용자 정보를 복구하지 못함.
    3. `localStorage`에 토큰이 제대로 저장되지 않았을 가능성 (낮음, 로그인 직후는 되니까).

## 2. 코드 분석 (AuthContext.jsx)
현재 `initAuth` 로직:
```javascript
const initAuth = async () => {
    const token = localStorage.getItem('auth_token');
    if (token) {
        try {
            const payload = jwtDecode(token);
            // ... 사용자 정보 구성 ...
            setUser(userState);
        } catch (error) {
            console.error("Critical Auth check failed...");
            localStorage.removeItem('auth_token');
            setUser(null);
        }
    } else {
        setUser(null);
    }
    setIsLoading(false);
};
```
- 로직 자체는 정상적으로 보이나, `payload`에서 데이터를 꺼내는 부분이나 `token` 유효성 검증에서 문제가 생길 수 있음.

## 3. 해결 계획 (To-Be)
1. **디버깅 강화**: `initAuth` 흐름에 `console.log`를 추가하여 어디서 실패하는지 정확히 파악하도록 요청.
2. **토큰 검증 로직 보완**:
    - `jwtDecode`가 실패하더라도, 최소한의 정보로 로그인 상태를 유지하도록 방어 코드 작성.
    - 토큰 만료 시간(`exp`) 확인 로직 추가 (만료된 토큰이면 로그아웃 처리).

## 4. 검증 절차
1. `AuthContext.jsx` 수정 (디버그 로그 추가 및 안정성 강화).
2. 브라우저 콘솔(F12) 열기.
3. 로그인 -> 새로고침 -> 콘솔 로그 확인 (`[Auth Debug] ...`).
4. 유저 상태가 유지되는지 확인.

## 5. 조치 결과 및 확인 가이드 (2025-12-30 업데이트)
`AuthContext.jsx`에 디버그 로그와 방어 로직을 추가했습니다.

**확인 방법:**
1. 브라우저 개발자 도구(F12) -> Console 탭 클릭.
2. 페이지 새로고침.
3. `[Auth Debug]`로 시작하는 로그 확인.

**로그별 의미:**
- `[Auth Debug] Init checking token: Found`: 토큰이 localStorage에 있음 (정상).
- `[Auth Debug] Decoded Payload: {...}`: 토큰 해독 성공.
    - 만약 여기서 멈추고 에러가 난다면, 토큰 형식이 이상한 것.
- `[Auth Debug] Token expired`: 토큰 수명이 다해서 로그아웃 처리됨. (다시 로그인 필요)
- `[Auth Debug] Setting User: {...}`: **성공!** 세션이 복구됨.

만약 여전히 풀린다면, `Critical Auth check failed` 에러 메시지를 알려주세요.

## 7. 최종 해결 완료 (2025-12-30 16:45)
**1. 최고 점수 0점 이슈**
- **원인**: 테스트 중 DB가 초기화되어 실제로 점수 기록이 없었음.
- **조치**: `web_mypage.py`에 안전장치 추가 (하이스코어 테이블에 없으면 유저 정보의 점수 사용).

**2. 로그인 세션 유지 이슈**
- **원인**: `cognito.js`가 이메일 정보가 없는 `AccessToken`을 저장하고 있었음.
- **조치**: 이메일 등 유저 정보를 포함하는 `IdToken`을 저장하도록 수정함.
- **결과**: 새로고침 시에도 이메일(`kimujin24@gmail.com`)이 정상적으로 복구됨.
