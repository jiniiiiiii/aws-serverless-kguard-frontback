# 마이페이지 구성 및 데이터 연동 계획

## 1. 현상 분석 (AS-IS)
1.  **`getUserProfile` API 문제**:
    *   `src/services/api.js`에 정의된 `getUserProfile`이 `/s3-my-page/profile.json`이라는 존재하지 않는 S3 경로를 참조하고 있어 404 에러 및 혼란을 야기할 수 있음.
    *   현재 프론트엔드(`MyPage.jsx`)는 `useAuth`를 통해 기본 프로필(이메일 등)을 가져오고 있으며, 이 API는 사용하지 않는 것으로 파악됨.
2.  **마이페이지 데이터 연동 실패**:
    *   사용자는 마이페이지에서 `high_score` 테이블의 점수와 랭킹을 보고 싶어함.
    *   `web_mypage.py`가 이를 처리하려 시도하고 있으나, 코드 내 **치명적인 변수명 오타**(`RANKING_LAMBDA_NAME` 정의되지 않음)로 인해 람다 호출이 실패함.
    *   이로 인해 점수와 랭킹이 0으로 표시되거나 에러가 발생함.
3.  **글로벌 랭킹 미표시**:
    *   마이페이지 UI는 `topPercent` 등을 기대하나 백엔드에서 이를 계산해주지 않음.

## 2. 개선 계획 (TO-BE)

### Backend (`web_mypage.py` 수정)
1.  **변수명 수정**: 정의되지 않은 `RANKING_LAMBDA_NAME`을 `HIGHSCORE_LAMBDA_NAME`으로 수정하여 `high_score_lambda`를 정상적으로 호출하도록 함.
2.  **데이터 통합**:
    *   `high_score_lambda`로부터 받은 `rank`, `score`를 응답 데이터에 확실하게 매핑.
    *   `region` 정보도 `high_score` 테이블이나 환경변수에서 가져오도록 보정.

### Frontend (`src/services/api.js` & `MyPage.jsx`)
1.  **`getUserProfile` 정리**: 사용하지 않고 오류를 유발하는 `/s3-my-page` 관련 코드 제거 또는 주석 처리.
2.  **`MyPage.jsx` 데이터 표시**:
    *   백엔드에서 오는 실제 데이터를 `stats` state에 올바르게 연동.
    *   `topPercent` 등 계산이 복잡한 필드는 일단 숨기거나 간단한 로직(예: 랭킹 기반 추산)으로 대체 표시.

### IAM Policy Check
*   `web_mypage` 람다가 `high_score_lambda`를 호출(`lambda:InvokeFunction`)할 권한이 있는지 확인 필요 (`policy_mypage_lambda.json` 점검).

## 3. 작업 순서
1.  **[Backend]** `web_mypage.py` 코드 수정 (오타 수정 및 로직 보강).
2.  **[IAM]** `policy_mypage_lambda.json` 권한 확인 및 필요 시 수정.
3.  **[Frontend]** `api.js`에서 불필요한 S3 호출 코드 정리.
4.  **[Frontend]** `MyPage.jsx`에서 `topPercent` 예외 처리.

이 계획대로 진행하여 마이페이지에서 **내 실제 점수와 랭킹(High Score DDB 원천)**을 볼 수 있도록 하겠습니다. 승인해 주시면 즉시 진행하겠습니다.
