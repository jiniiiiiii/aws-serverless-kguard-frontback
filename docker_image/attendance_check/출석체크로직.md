# 프로젝트 프로필: ECS 출석체크 서비스 (Attendance Check) - 연속 출석 기능 포함

## 1. 개요
- **목표**: AWS ECS Fargate 상에서 동작하는 **Node.js 기반 마이크로서비스** 구축 및 **연속 출석 보상 시스템** 구현.
- **역할**: 사용자의 일일 출석 여부를 확인하고, 연속 출석 횟수에 따라 차등 보상(Gold)을 지급.
- **기술 스택**: Node.js, Express, AWS SDK v3 (DynamoDB), Docker

## 2. 아키텍처 및 데이터 흐름
`User (Web)` -> `ALB` -> `ECS Container (Node.js)` -> `DynamoDB`
- **특이사항**: 별도의 Lambda나 Streams 없이, **Node.js 애플리케이션 레벨**에서 판단 로직을 수행합니다.

## 3. 핵심 로직: 연속 출석 (Consecutive Streak)
기존의 단순 "오늘 날짜 기록"에서, **"어제 출석 여부 확인 후 연속 카운트 증가"** 로직으로 변경됩니다. 이를 위해 **Read-Modify-Write** 패턴을 사용합니다.

### 데이터 모델 (DynamoDB Attributes)
| 필드명 | 타입 | 설명 |
| :--- | :--- | :--- |
| `user_id` | String | (PK) 사용자 ID |
| `last_attendance_date` | String | 마지막 출석 날짜 (YYYY-MM-DD, KST 기준) |
| `consecutive_streak` | Number | 현재 연속 출석 횟수 (1부터 시작) |
| `gold` | Number | 재화 |

### 로직 시퀀스 (Sequence Logic)

1.  **조회 (Read)**: `user_id`로 DB에서 `last_attendance_date`, `consecutive_streak`를 가져옵니다.
    -   *If* 데이터가 없으면: 신규 유저 취급.
2.  **계산 (Calculate in Memory)**:
    -   `today` = KST 오늘 날짜.
    -   `yesterday` = KST 어제 날짜.
    -   **Case 1: 오늘 이미 출석함 (`last_attendance_date == today`)**
        -   -> 에러 반환 ("이미 출석했습니다.")
    -   **Case 2: 연속 출석 (`last_attendance_date == yesterday`)**
        -   `new_streak` = `consecutive_streak` + 1
    -   **Case 3: 연속 깨짐 (`last_attendance_date < yesterday` OR null)**
        -   `new_streak` = 1
3.  **보상 결정**:
    -   기본 보상: 10 Gold
    -   **보너스 보상**: `new_streak`가 3일, 7일, 30일 등 특정 구간 도달 시 추가 지급.
        -   *예시*: 3일 연속 시 +30 Gold 추가.
4.  **저장 (Write)**:
    -   `UpdateItem` 수행.
    -   **ConditionExpression (중요)**: `last_attendance_date`가 **1번 단계에서 읽은 값과 같을 때만** 업데이트.
        -   이유: 그 사이 중복 요청이 들어와서 이미 업데이트 되었을 수 있음 (동시성 방지).

## 4. 구현 가이드 (Pseudo Code)

```javascript
// 1. Get User Info
const { Item } = await docClient.send(new GetCommand({ Key: { user_id } }));
const lastDate = Item?.last_attendance_date;
const currentStreak = Item?.consecutive_streak || 0;

// 2. Calculate Logic
const today = getKSTDate();      // "2024-05-20"
const yesterday = getYesterday(); // "2024-05-19"

if (lastDate === today) {
    return fail("Already attended");
}

let newStreak = 1;
if (lastDate === yesterday) {
    newStreak = currentStreak + 1;
}

// 3. Calculate Reward
let reward = 10;
if (newStreak === 3) reward += 30; // 3일 연속 보너스

// 4. Update DB (Optimistic Locking)
try {
    await docClient.send(new UpdateCommand({
        Key: { user_id },
        UpdateExpression: "SET gold = gold + :r, last_attendance_date = :t, consecutive_streak = :s",
        ConditionExpression: "last_attendance_date = :oldDate", // OR attribute_not_exists if new
        ExpressionAttributeValues: {
            ":r": reward,
            ":t": today,
            ":s": newStreak,
            ":oldDate": lastDate // 읽어온 값과 비교
        }
    }));
    return success({ streak: newStreak, reward });
} catch (e) {
    if (e.name === 'ConditionalCheckFailedException') {
        return fail("Conflict or Already updated");
    }
    throw e;
}
```

## 5. 기존 방식 vs 변경 방식 비교

| 구분 | 기존 (단순 업데이트) | 변경 (로직 기반 업데이트) |
| :--- | :--- | :--- |
| **방식** | `UpdateItem` with `Condition` | `GetItem` -> Logic -> `UpdateItem` |
| **장점** | 쿼리 1회로 빠름, 비용 절약 | 복잡한 로직(연속 출석, 보너스) 구현 가능 |
| **단점** | 연속 출석 판별 불가 (이전 날짜 모름) | 쿼리 2회 발생 (비용 소폭 증가) |
| **적합성** | 단순 출석 체크 | **연속 출석 & 보상 시스템** |
