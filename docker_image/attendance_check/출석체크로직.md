# 프로젝트 프로필: ECS 출석체크 서비스 (Attendance Check)

## 1. 개요
- **목표**: AWS ECS Fargate 상에서 동작하는 **Node.js 기반 마이크로서비스** 구축.
- **역할**: 사용자의 일일 출석 여부를 확인하고 보상(Gold)을 지급.
- **기술 스택**:
    - **Runtime**: Node.js (v18+)
    - **Framework**: Express.js
    - **AWS SDK**: AWS SDK for JavaScript v3 (DynamoDB Client)
    - **Container**: Docker (Alpine Linux 기반 경량화)

## 2. 아키텍처 및 데이터 흐름
`User (Web)` -> `ALB (Load Balancer)` -> `ECS Container (Node.js)` -> `DynamoDB (User Table)`

*   **별도의 Lambda가 필요하지 않습니다.**
*   ECS 컨테이너가 직접 AWS Credential(Task Role)을 이용해 DynamoDB에 접근하고 데이터를 수정합니다.

## 3. 핵심 로직 (Sequence Thinking)
**API Endpoint**: `POST /attendance`

1.  **요청 수신**: 클라이언트로부터 `user_id` (또는 토큰) 수신.
2.  **현재 시간 확인**: 한국 시간(KST) 기준 '오늘 날짜'(`YYYY-MM-DD`) 생성.
3.  **DB 조회 (GetItem)**: `KG-db-ddb-ap-ne-2-userdata` 테이블에서 유저 정보 조회.
    -   *Check*: `last_attendance_date` 필드 확인.
4.  **조건 분기**:
    -   **Case A (이미 출석함)**: `last_attendance_date == 오늘 날짜`
        -   -> 응답: `{ status: "fail", message: "이미 출석했습니다." }`
    -   **Case B (출석 가능)**: `last_attendance_date != 오늘 날짜` 또는 필드 없음.
        -   -> **DB 업데이트 (UpdateItem)**:
            -   `Gold`: `Gold + 10` (Atomic Counter)
            -   `last_attendance_date`: `오늘 날짜`
        -   -> 응답: `{ status: "success", reward: 10, currentGold: ... }`

## 4. 해결 과제 (Q&A)

### Q1. DDB에 오늘 날짜를 어떻게 기록하나요? 람다가 필요한가요?
**A. 람다는 필요 없습니다!**
ECS에 띄울 **Node.js 서버**가 그 역할을 대신합니다.
Node.js 코드 안에서 `new Date()`로 시간을 구하고, `dynamoClient.send(new UpdateItemCommand(...))`를 실행하여 직접 DB 값을 바꿔버리면 됩니다.

# 5. 구현 단계
1. 디렉토리 생성
    mkdir attendance-service && cd attendance-service
    npm init -y
    ```
2.  **필수 패키지 설치**:
    - `express`: 웹 서버 프레임워크
    - `@aws-sdk/client-dynamodb`, `@aws-sdk/lib-dynamodb`: DynamoDB V3 SDK
    - `dotenv`: 환경 변수 관리
    ```bash
    npm install express @aws-sdk/client-dynamodb @aws-sdk/lib-dynamodb dotenv
    ```

### 2단계: 서버 로직 구현 (`index.js`)
1.  **KST 시간 처리**: `Intl.DateTimeFormat`을 사용하여 서버 위치와 상관없이 한국 날짜(`YYYY-MM-DD`)를 생성합니다.
2.  **Atomic Update 실행**: `UpdateCommand`의 `ConditionExpression`을 활용하여 "오늘 이미 출석한 경우" DB 수준에서 업데이트를 거부하도록 설계합니다.
    - `UpdateExpression`: `SET Gold = Gold + :inc, last_attendance_date = :today`
    - `ConditionExpression`: `last_attendance_date <> :today`


### 로컬 테스트 방법
1. 의존성 설치
    ```bash
    npm install
    ```
2. 환경 변수 설정
    ```bash
    cp .env.example .env
    ```
3. 서버 실행
```bash
node index.js
```

aws 자격증명이 되어있다면 바로 동작함
aws 자격증명이 되어있지 않다면 아래와 같이 실행
    ```bash
    AWS_ACCESS_KEY_ID=your_access_key AWS_SECRET_ACCESS_KEY=your_secret_key node index.js
    ```



### 3단계: Docker 이미지 최적화 (`Dockerfile`)
1.  **멀티 스테이지 빌드** 또는 **Alpine 이미지**를 사용하여 용량 최소화.
2.  **환경 변수 설정**: `PORT=3000`, `NODE_ENV=production`.
3.  **Health Check**: ECS가 컨테이너 상태를 확인할 수 있도록 `/health` 엔드포인트 추가.

### 4단계: AWS 인프라 및 권한 설정
1.  **IAM Task Role**: ECS 컨테이너가 DynamoDB에 접근할 수 있도록 `dynamodb:UpdateItem`, `dynamodb:GetItem` 권한을 가진 Role을 생성하고 Task Definition에 할당합니다.
2.  **ECR Repository**: 빌드한 이미지를 푸시할 저장소를 생성합니다.
3.  **ECS Service**: Fargate를 사용하여 서버를 띄우고, ALB(Application Load Balancer)를 통해 외부 트래픽을 수용합니다.

### 5단계: 배포 및 테스트
1.  **이미지 빌드 및 푸시**:
    ```bash
    docker build -t attendance-check .
    docker tag attendance-check:latest [AWS_ACCOUNT_ID].dkr.ecr.[REGION].amazonaws.com/attendance-check:latest
    docker push [AWS_ACCOUNT_ID].dkr.ecr.[REGION].amazonaws.com/attendance-check:latest
    
1.  **프로젝트 세팅**: `npm init`, `express`, `@aws-sdk/client-dynamodb` 설치.
2.  **로직 구현**: `server.js` 작성 (KST 시간 계산 주의).
3.  **Docker화**: `Dockerfile` 작성 및 로컬 빌드 테스트.
4.  **배포**: ECR 푸시 -> ECS Task Definition 등록 -> Service 실행.
