# 랭킹 시스템 로직 (Ranking System Logic)
*(작성일: 2025-12-29)*

이 문서는 프로젝트에 적용된 **두 가지 랭킹 시스템(개인 랭킹 / 전체 랭킹)**의 작동 원리와 데이터 흐름을 설명합니다.

---

## 1. 아키텍처 개요 (Overview)
본 프로젝트는 목적에 따라 **Redis**와 **DynamoDB**를 혼용하여 랭킹을 처리합니다.

| 구분 | **개인 랭킹 (MyPage)** | **전체 랭킹 (Global Ranking)** |
| :--- | :--- | :--- |
| **목적** | 내 순위와 점수를 빠르게 확인 | 전체 유저 중 Top 100 리스트 확인 |
| **핵심 자원** | **Redis** (ElastiCache) | **DynamoDB** (Highscore Table) |
| **담당 Lambda** | `web_mypage.py` (+ `ranking.py`) | `high_score_lambda.py` |
| **특징** | 람다 간 호출(Invoke) 사용 | 스트림 저장 & API 조회 겸용 |

---

## 2. 상세 로직 설명

### A. 마이페이지 랭킹 (Personal Rank)
사용자가 마이페이지에 접속했을 때 보여주는 "내 순위" 로직입니다.

**[Data Flow]**
`Client` → `API Gateway` → `web_mypage.py` ⇄ `ranking.py` (Redis)

**[작동 순서]**
1.  **요청 수신**: `web_mypage.py`가 실행됩니다.
2.  **기본 정보 조회**: `Userdata` DynamoDB 테이블에서 골드, 레벨, 가입일 정보를 가져옵니다. (매우 빠름)
3.  **랭킹 람다 호출 (Invoke)**: 
    *   `web_mypage.py` 내부에서 `boto3`를 사용해 **`ranking.py` 람다를 직접 호출**합니다.
    *   Payload: `{ "action": "get_my_rank", "user_id": "..." }`
4.  **Redis 조회**: 호출받은 `ranking.py`는 VPC 내부의 **Redis**에 접근하여 `ZREVRANK`로 순위를 조회합니다.
5.  **병합 및 반환**: 두 정보를 합쳐서 클라이언트에게 한 번에 내려줍니다.

---

### B. 전체 랭킹 (Global Ranking)
게임의 "랭킹 페이지"에서 보여주는 실시간 Top 100 리스트입니다.

**[Data Flow]**
`Client` → `API Gateway` → `high_score_lambda.py` → `DynamoDB`

**[작동 순서]**
1.  **데이터 적재 (평상시)**: 
    *   유저가 게임을 하면 `Userdata` 테이블이 업데이트됩니다.
    *   이때 발생하는 **DynamoDB Stream**을 `high_score_lambda.py`가 감지하여 `Highscore` 테이블에 이력을 쌓습니다. 
    *   **저장 정보**: `user_id` (cognito 이메일), `score` (최고점수), `region` (가입 지역), `timestamp`
2.  **랭킹 조회 (요청시)**:
    *   클라이언트가 랭킹 API를 호출합니다.
    *   `high_score_lambda.py`는 `Highscore` 테이블을 **Scan**합니다.
3.  **집계 (Aggregation)**: 
    *   한 유저의 점수 기록이 여러 개일 수 있으므로, 메모리 상에서 **유저별 최고 점수(Max Score)**만 남기고 중복을 제거합니다.
4.  **정렬 및 반환**:
    *   점수 기준 내림차순 정렬 후, 상위 100개만 잘라서 반환합니다.
    *   **필수 반환 필드**:
        *   `rank`: 순위
        *   `user_id`: 사용자 이메일 (UI에서 "User_id" 및 "cognito 로그인 메일"로 표시됨)
        *   `score`: 최고 점수 ("highscore"로 표시됨)
        *   `region`: 가입 지역 ("가입 지역"으로 표시됨)

---

## 3. 핵심 파일 및 위치
*   `backend_lambda/web_mypage.py`: 마이페이지 메인 로직 (랭킹 람다 호출자)
*   `backend_lambda/ranking.py`: Redis 전용 람다 (VPC 내부)
*   `backend_lambda/high_score_lambda.py`: DDB 스트림 처리 및 전체 랭킹 집계
*   `web-portal/src/pages/Ranking.jsx`: 랭킹 페이지 UI (이메일, 점수, 지역 표시)

## 4. 변경 이력 및 주의사항
*   **(2025-12-29 업데이트)**: 전체 랭킹 UI가 **User_id (이메일)**, **Highscore**, **가입 지역**을 보여주도록 변경되었습니다. 이에 따라 백엔드 API도 해당 필드(`region` 등)를 반드시 반환해야 합니다.
*   **권한**: `web_mypage` 람다가 다른 람다를 부르기 위해 IAM 정책에 `lambda:InvokeFunction` 권한이 필수입니다.
*   **성능**: 전체 랭킹 조회 시 데이터가 많아지면 `Scan` 방식은 느려질 수 있습니다. 추후 `Highscore` 테이블에 GSI(Global Secondary Index)를 추가하여 쿼리 효율을 높이는 것이 좋습니다.
